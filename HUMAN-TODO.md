# HUMAN-TODO: steps only Amaan can do

Same format as Drive's HUMAN-TODO.md (pluggable hosting, Drive PR #3). Tick the box when done. Nothing in the
pluggable-hosting PR bought, created or changed anything at a provider, Cloudflare or Backblaze; every item below is a
decision or an action that has to be a person.

- [ ] **H-01 Secrets file.** Create `C:/projects/secrets/pd.env` yourself (do not paste secrets into chat); the keys are listed in `config/secrets.env.example`: `CLOUDFLARE_DNS_TOKEN` (Zone > DNS > Edit, zone shaavir.com only), `B2_KEY_ID` / `B2_APP_KEY`, `SSH_PUBKEY_PATH` (key `amaan-ed25519`), `ADMIN_IP` (your current public IP, for the first-boot SSH window), plus the key of the chosen provider (H-02). This is the laptop file; the server's `/opt/pd/.env` is separate.
- [ ] **H-02 Production provider and server order (open question Q-02).** Decide which adapter runs production (`[infra] provider` in `config/tenant.toml`: `ovh-us`, `hetzner` or `ssh`; default `ssh`). For `ssh`: order an Ubuntu 24.04 server in the provider's panel (an OVH US VPS is an `ssh` server), install the root key, fill `[infra.ssh]` (ipv4, ipv6, panel_url) and **`[infra] subprocessor`** (the hosting company's legal name; deploy.sh refuses an empty one). For `ovh-us` / `hetzner`: put the API credential / `HCLOUD_TOKEN` in `pd.env`, then `infra/provision.sh --dry-run` and, after your go-ahead, `--confirm-purchase`. Purchases are your call.
- [ ] **H-03 Backblaze B2 bucket `shaavir-pd-backup-us`.** Create it private, with a lifecycle rule that deletes hidden versions after N days; a **server key** limited to the bucket and prefix `shaavir-pd` **without `deleteFiles`**; a **read-only restore key** for the drill; the two rclone crypt passwords into the password manager. Then `sudo ops/backup/rclone-setup.sh` on the server. There is no B2 API script on purpose (`ops/backup/README.md`).
- [ ] **H-04 Borg passphrase and exported key** into the password manager: create `/etc/pd/borg.pass` (root, 0400), run `sudo infra/scripts/backup.sh --init`, copy the passphrase and `/etc/pd/borg-key.txt` to the vault, `shred -u /etc/pd/borg-key.txt`.
- [ ] **H-05 LUKS recovery passphrases and header backups** when `infra/luks/format-volumes.sh` runs, after your go-ahead (no test runs a LUKS format): two recovery passphrases and the two header backups in the password manager.
- [ ] **H-06 Headscale policy for `tag:pd`.** On shaavir-prod-01 (Drive repository and host; this PR does not edit Drive) add `tag:pd` to `tagOwners` and an ACL `group:admins -> tag:pd:22`. Then create a pre-auth key for `tag:pd` and run `sudo infra/headscale/server-join.sh` on the PD server. Until then SSH works only in the bootstrap window or through the provider console (Q-07).
- [ ] **H-07 GitHub deploy settings.** Create the environment `production` with a required reviewer. Secrets: `PD_DEPLOY_HOST` (the server's admin-network name or IP), `PD_DEPLOY_SSH_KEY` (private key whose public half you give to `sudo infra/server/deploy-user.sh --pubkey FILE --confirm`), `PD_DEPLOY_KNOWN_HOSTS`, `PD_TS_AUTHKEY` and `PD_TS_LOGIN_SERVER` (Headscale; *verify* `tailscale/github-action@v3` with Headscale). Repository variable `PD_PUSH_IMAGES=true` only if you want images pushed to GHCR on every push to master (off by default, Q-16); check the package visibility (the repo is public).
- [ ] **H-08 `pdadmin` console password** (a word passphrase: provider consoles often have a US keyboard layout and no paste), into the password manager; you type it once when you use the console.
- [ ] **H-09 Counsel: hosting and backup subprocessors in the Privacy Policy** (plan 07 s4). The app now lists the hosting provider (from `[infra]`) and the off-site backup target (Backblaze, Inc., from `[backup] subprocessor`) in `GET /api/about/processing`; counsel confirms the published text before go-live, and again after any provider switch.
- [ ] **H-10 Enable the secret-scan hook per clone:** `git config core.hooksPath .githooks`. It needs a working Python 3 on the PATH (it blocks the commit rather than skip the scan when none is found).
