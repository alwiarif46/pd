# 05: User Interface

**Status:** Draft v2 · 17 Oct 2026

E2E Proposal promises a proposal with one click. E2E absorbs PD, so PD's tabs (overview, schedule, compliance matrix, outline, resumes, reviews, production, orals, lessons) live on as E2E screens (09 s7). The UI keeps that promise by asking for little and showing a lot. Every screen in a bid opens with what the tool already holds, then lists what it still needs.

## 1. Principles

| Principle | What it means on screen |
|---|---|
| Show first, ask second | Intake fetches from the tenant repository before it asks for anything. The screen leads with "We already have this" (s4.1) |
| One mandatory input | Only the solicitation package must be present to start. Every other input is optional at start and appears when the run needs it |
| No questionnaires | The tool never asks a question that the solicitation, the repository, or the evidence library already answers. Missing facts become NEEDs, not forms |
| Work never waits on the user | Drafting proceeds with NEED placeholders. The user fills them when convenient, up to the Red review (04 s6) |
| Humans decide at gates | Four places stop for a person: Gate 0b bid/no-bid, Gate 1 after Red, Gate 2 after Gold, and every send or submit click |
| Nothing changes silently | A human edit locks the block. Any proposed change to it shows as a proposal for approval (s4.8) |
| Plain status | Every stage, request, and page shows a short plain status. No raw error text |

## 4. Screens inside a bid

### 4.1 Soft intake (Gate 0)

The first screen after upload. The tool scans the package, reads the requirements, and searches the tenant repository and evidence library. Only then does the screen render.

**Layout:** two columns.

| Column | Contents |
|---|---|
| We already have this | Every input the tool found, grouped by kind: past performances, resumes, format spec, fonts, certificates, boilerplate, past sections, graphics. Each item shows its source (repository, evidence library, earlier bid) and its match to this solicitation |
| We still need this | Every input the tool could not find. Each row shows what it is, why the bid needs it, the requirement it serves (source link), and when the run needs it |

- Mandatory items carry a "Required" badge. At start, only the solicitation package carries it.
- Every other need shows "Needed before Red review". The run starts without them and drafts with NEEDs.
- Each need row has three actions: "Upload", "Request from someone" (opens s4.5 with the item prefilled), and "Use a placeholder for now".
- The user can swap or remove a found item. Removing one turns it into a need. The screen never asks the user to confirm items one by one.
- The marking prompt for CUI and export-control markings comes from PD (PD 05 s3.10).
- **AI-ban flag.** If the solicitation bans or restricts AI-generated content, a red banner sits at the top. It quotes the clause with its page and source link. The run is not held: "Start run" stays enabled, and the flag also shows in the bid/no-bid risk panel (04 s5.1; 07 s4).

**Estimate and start.** A panel at the bottom shows:
- Estimated cost and time, from page count and volume count (06 s7).
- Proposals left this month and the page allowance: "Up to 100 drafted pages. This bid budgets N."
- A tenant with its free proposal unused sees "Free proposal: up to 50 drafted pages" instead (06 s3).
- A note when the page budget exceeds 100: the recharge applies (06 s5). 🟨 **OPEN:** recharge rate.
- One button: "Start run". The amendment gate, shred, and matrix begin. Bid/no-bid comes next.

### 4.2 Bid/no-bid (Gate 0b)

Opens after the shred. The run holds here until a tenant user decides (04 s6; 06 s2).

| Panel | Contents |
|---|---|
| Fit | Scope match against the tenant's repository and evidence, with the requirements that drove it |
| Eligibility | Set-aside, size, clearances, certifications, licenses, registrations. Each item is "Met", "Not met", or "Unknown", with its source |
| Past performance coverage | Each required past performance area against the contracts the tool holds. Gaps listed |
| Risk | Page limits, deadlines, unusual clauses, AI-ban flag, missing mandatory forms |
| Summary | One score per panel and a plain recommendation. The person decides |

- Buttons: "Bid" and "No bid". "No bid" asks for an optional reason and closes the bid. Reasons feed the repository (s5).
- No-bid releases the proposal reserved at run start. So does a run that fails or is cancelled before the Red draft. The proposal is used only when the Red draft reaches Gate 1 (06 s4).

### 4.3 Run monitor

The home screen of a running bid.

- **Stage list.** Every stage from 04 s3 in order, each with status, start, end, and retries. The current stage is open by default.
- **Page grid.** Volumes as rows, sections as cells. Each cell shows its page gate score against 90%, NEED count, and lock count. Clicking a cell opens the page in the detail slider.
- **Cost meter.** Spend so far against the run's cost cap, including model and image cost (01 s8). The cap value comes from the 10-RFP test.
- **Time.** Elapsed time and the estimate to the next gate.
- **Pink review link.** Opens the Pink review document in the tenant's Shaavir Drive folder. A note says "Add anything here at any time."
- **Events feed.** Amendment received, Q&A deadline near, request reply received, stage failed, gate waiting.
- **Failed stage.** A plain reason and a "Retry" button. Retries resume from the saved stage state (04 s12).
- **Cost cap reached.** The run pauses with its state saved and a plain message (01 s8). Proposed: the vendor and the tenant Admin get an alert. 🟨 **OPEN:** who may raise the cap for a run and how (06 s8).

### 4.4 Amendment re-entry

An amendment can arrive at any time: uploaded on the Documents screen, or caught by the eBuy watcher.

- A banner on every screen of the bid: "Amendment N received. Reviewing changes."
- When the diff finishes, the banner opens a change list. Each change shows the old text, the new text, its source page, and the pages it reopens.
- Reopened pages show "Reopened by Amd N" in the page grid and run back through the page gate.
- A change that touches a locked block never edits it. It shows as a proposed change for approval (s4.8).
- Compliance matrix rows follow the PD amendment display: superseded, withdrawn, and added (PD 05 s3.3).
- A Q&A release follows the same path as an amendment.

### 4.5 Q&A review and send

| Area | Contents |
|---|---|
| Deadline | Countdown to the Q&A deadline, with its source link. Alerts fire before it (s7) |
| Format | The format the solicitation requires, quoted with its source. If the agency supplied a questionnaire document, a preview of it filled in |
| Questions | Each drafted question with the requirement or page it concerns, a reason, and Edit, Delete, and Add |
| Email | To, Cc, subject, body, and attachments. "From" is the tenant's connected mailbox address |

- Two checkboxes gate the send: "I reviewed the questions" and "I reviewed the email". Both start unchecked.
- "Send" stays disabled until the user checks both and connects a mailbox (s6).
- After sending, the screen shows the sent copy, time, and sender. The tool never sends Q&A without this click.
- With no mailbox connected, the screen offers "Download questions and email" and "Connect a mailbox".

### 4.6 Request and collect tracker

Commitment letters, partner past performance forms, resume consents, and similar third-party items.

| Column | Contents |
|---|---|
| Item | What the tool requests, and the requirement it serves (source link) |
| Requestee | Name and email |
| Format | The required format or form, with a preview of the request |
| Due | Date the bid needs the item, always before the Red review |
| Status | Draft, Sent, Reply received, Accepted, Rejected, Overdue |
| Received file | Link to the collected reply or upload |

- New requests come from intake (s4.1) or from "Add request" here.
- Requests go out from the tenant's mailbox through its email connection. Replies return through the same connection.
- Every row also has "Upload instead", for items received another way.
- A received reply shows the attachment and a check result: right form, signed where needed, readable. A person accepts or rejects it.
- 🟨 **OPEN:** whether each request email needs a human click before it goes, like Q&A, or the tool sends it on its own. Proposed: a human click (07 s3).
- 🟨 **OPEN:** automatic reminders to requestees, and how often.

### 4.7 Red review (Gate 1)

Opens when the separate reviewer model finishes the Red team review.

**Summary bar:**
- Predicted rating per evaluation factor, with the factor name as the solicitation states it.
- Counts: findings open, NEEDs open, pages under 90%.
- "Approve and continue" button. It stays disabled until every finding has a disposition.

**Three panels:**

| Panel | Contents |
|---|---|
| Pages | Every page with its score, a thumbnail, and a filter for pages under 90% |
| Findings | Each finding with type (strength, weakness, deficiency, risk), factor, quote, page, and the suggested fix. Actions: Accept, Edit, Reject |
| NEEDs | Ranked by score impact, highest first. Each shows the missing fact, the page, and the placeholder text. Actions: Fill, Upload, Request, Mask |

- "Mask" writes the page around the missing fact. A person must choose it; the tool never masks on its own (04 s6).
- The page view shows the rendered page beside an editable text view. Editing a block locks it (s4.8).
- An edited finding keeps the reviewer's text and the user's version side by side.
- Approve sends the dispositions to the run. The run re-drafts flagged pages around locked blocks, then continues to Gold (04 s6).

### 4.8 Locks

- A locked block shows a lock icon, the editor, and the time.
- Hover shows "Fixed text. The tool writes around it."
- A user can unlock a block. The unlock goes to the audit log (04 s8).
- **Proposed change to locked text.** When the model thinks a locked block must change, the block shows a yellow "Change proposed" tag. Opening it shows the current text, the proposed text, and the reason. Actions: Approve, Edit, Reject.
- Proposed changes collect on the Red review and Sign-off screens with a count, so none slip past.

### 4.9 Sign-off (Gate 2)

Opens after Gold Team and White Glove review.

- **Round diff.** A round selector (Draft, After Red, After Gold, and any later rounds). The page view shows two rounds side by side. Highlights mark changed blocks. Each change names the finding or amendment that caused it.
- **Page list.** Pages with any change, so the reviewer can step through only those.
- **Per volume.** Page count on the exact PDF against the limit, the visual check result per page and Gold and White Glove notes. The visual check covers overflow, broken tables, cut-off graphics, orphan headings, and margins.
- **Uncited claims.** Any past performance, staffing, or figure claim without an evidence citation appears in a list. Assembly blocks the package until each carries a citation or comes out (07 s5).
- Each volume has "Confirm volume". "Sign off" stays disabled until the user confirms every volume.
- Sign-off records the user and time. The package build starts.

### 4.10 Package and signature notice

- **One download.** A single button gets the whole package. File names follow the solicitation's naming rule.
- **Contents list.** Volumes in Word and PDF, completed forms, attachments, compliance matrix, and submission checklist. Each item shows its status.
- **Signature and review notice.** A panel at the top lists what needs a signature and what needs review. Reps and certs always appear under review. The tool fills details and never signs (07 s6).
- **Word-only submissions.** When the solicitation requires Word files, a note at the end of the package says: "Check the page limit in Word before you submit."
- **Submission.** Two choices, per portal:
  - "Upload it yourself": the guided checklist for that portal.
  - "Let the agent help": a browser agent session. The screen shows the agent's view live. Each login and MFA step stops for the user to approve. Credentials are never stored (07 s2).
- Portals that ban automation, such as SAM.gov, show only the upload choice and the checklist.
- The final submit click is always the user's. The agent never clicks it.
- After submission, the bid shows "Record the outcome". It feeds the repository and the learning loop (s5).

### 4.11 Documents and bid settings

- Documents reuses PD's Documents tab (PD 05 s3.10): upload checks, marking prompt, amendment number, status per file.
- Each document also shows its copy in the tenant's Shaavir Drive folder, with a link.
- Bid settings reuses PD (PD 05 s3.11) and adds the bid's format spec, the volumes, and the page budget per volume.

## 5. Repository browser

The tenant's own store of everything from past proposals. Intake reads from it first (s4.1).

| Area | Contents |
|---|---|
| Filters | Agency, evaluation factor, section type, contract, date, outcome |
| Item kinds | Sections, designs, graphics, past performance write-ups, resumes, boilerplate, format specs, cover letters, forms |
| Item view | The item, its source bid, its scores, the dispositions it received, and where later bids reused it |
| Outcome entry | Per bid: award result (won, lost, cancelled, no decision), the debrief upload, and notes |

- Outcomes and debriefs feed the learning loop and gate calibration (04 s6).
- A user can retire an item so intake stops offering it. Retired items stay searchable.
- The repository shows only the tenant's own items. Nothing from another tenant ever appears (07 s1).

## 6. Settings

| Page | Contents |
|---|---|
| Fonts | Installed fonts, with the metric-compatible font the render service uses for each Microsoft font name (for example Liberation Serif for Times New Roman). A "Request a font" button |
| Request a font | Font name, an upload field for a commercial font, and a license checkbox: "We hold a license to use this font." A notice states the one-time fee. It also says the fee does not license the font. 🟨 **OPEN:** font fee amount |
| Mailbox | Connect Gmail or Microsoft 365. Shows the sending address, the connection status, and "Disconnect" |
| Shaavir Drive | The tenant's folder link, the users who share it, and a note that Shaavir's Drive stores client data (07 s8) |
| Portals | Per portal: "Upload myself" or "Agent with my approval". Banned-automation portals show upload only. A note: "We never store your portal passwords" |
| eBuy inbound | The tenant's inbound address with a copy button, setup steps, and the last message received. A "Daily check" switch with its last run time |
| Format specs | The tenant's house styles. Uploading a submitted proposal captures a new spec |
| Data and AI | AI providers, the image provider, subprocessors, and links to the Terms and Privacy Policy (07 s10) |
| Billing | Plan, proposals left, reset date, usage, and the Stripe portal (06) |

## 7. Notifications

| Event | Who |
|---|---|
| Gate waiting (0b, 1, 2) | Bid members |
| Q&A deadline near | Bid members |
| Amendment received | Bid members |
| Request reply received or overdue | The user who sent the request |
| Stage failed after retries | Bid members |
| Cost cap reached | Bid members and the tenant Admin |
| Package ready, with the signature and review notice | Bid members |

- In-app notifications always show. 🟨 **OPEN:** email notifications, their channel, and the alert lead times for the Q&A deadline.

## 8. States every screen handles

| State | Shows |
|---|---|
| Not reached yet | When the screen will open, and what it waits on |
| Running | Stage name, progress, and time estimate |
| Needs you | The decision or input, with one primary button |
| Paused at cost cap | Spend, cap, and who can act (s4.3) |
| Failed | Plain reason and "Retry". No raw error text |
| Out of proposals | Proposals left, reset date, upgrade or Enterprise contact |
| Disconnected | Mailbox or portal connection lost, with "Reconnect" |

## 9. Accessibility and quality bar

PD's bar applies in full (PD 05 s5). Added rules:
- Lock, change, and status tags carry a text label, never color alone.
- The round diff marks changes with text labels ("Added", "Removed") as well as color.
- Page images carry the page number and volume in their accessible name.
