## 3. Tabs

Tabs 3.1 to 3.8 hold source-bearing rows. Clicking any such row opens the row detail slider (3.12). Source links open the source viewer (3.13).

### 3.1 Bid overview and kickoff (free)
- Bid facts table: field, value, source page link, confirm checkbox. AI fills it; the user edits.
- Kickoff checklist: standard items (roles, schedule agreed, compliance matrix owner, page budgets, data calls, review dates), each with owner and done.
- Countdown to due date and time.
- A fact changed by an amendment shows the old value crossed out with "Superseded by Amd N".

### 3.2 Schedule (free)
- Port of the offline Proposal Schedule Builder: calendar and milestone list views, activities from a dropdown or custom, multi-day spans, drag to move, locks, date-change prompt (shift, scale, keep), templates, holidays.
- Dates extracted from the solicitation arrive as locked activities with a source link.
- An amendment that changes dates updates the locked activities and opens the shift, scale, or keep prompt (3.11).
- Exports: XLSX, ICS, CSV, print.

### 3.3 Compliance matrix (free)
- Table columns: ID, section, requirement, type, instruction ref, evaluation factor, response section, owner, status, source, amendment. On federal bids (`bid_type` = `federal`) the two reference columns are labelled "L ref" and "M factor".
- Click a row to open the row detail slider. Click a source to open the source viewer.
- Amendment display:
  - A superseded row stays, crossed out, with the note "Superseded by Amd N". Clicking the note jumps to the row or section that replaces it.
  - A new row shows "Added by Amd N".
  - A removed requirement with no replacement stays, crossed out, with "Withdrawn by Amd N". There is no jump target.
  - "Confirm amendment changes" lists the links the model is unsure of: the old row beside the proposed new row, with Confirm and Reject. Until confirmed, the old row stays active. Each proposal can show the amendment text behind it (`sourceQuote`, `sourcePage`). Decisions are final. Every row an amendment adds is in the matrix at once ("Added by Amd N"), whatever the model's confidence; only replacements and withdrawals are proposed.
  - Deleting or merging away a row that a proposal would bring in rejects that proposal. Deleting a row that replaced another keeps the old row "Superseded by Amd N", with no jump.
- Filters: section, type, status, owner, amendment, "flagged" (rows Pass 3 thinks may not be requirements, page-estimated rows, OCR rows), "hide superseded and withdrawn", "check these" (pre-scan hits with no row).
- Add, edit, merge, split, delete rows. User-made rows show "added by user".
- Banner while processing: step names with progress and queue position. Banner after: "Draft. Review every row before you rely on it."
- Export: XLSX laid out by the instruction sections (Section L on federal bids), and CSV. Superseded and withdrawn rows export with their status.

### 3.4 Outline and status tracker (paid)
- Tree of volumes and sections with number, title, page limit, writer, status, due date.
- Page budget total per volume against the limit, in red when over.
- Each section's source ref opens the row detail slider.
- Export: XLSX and DOCX (outline as headings).

### 3.5 Resume and key personnel matrix (paid)
- Left: roles and requirements extracted from the solicitation (editable).
- Upload resumes and assign each to a role.
- Grid: requirement rows × candidate columns, with meets, partial, gap, or unknown, and evidence on hover.
- Gap list per candidate, and a summary of roles with no candidate who meets all requirements.
- Resumes, their text, and evidence quotes are deleted 90 days after upload. Candidate names and results stay; evidence shows "Removed: resume deleted after 90 days".
- Export: XLSX.

### 3.6 Color team reviews (paid)
- Create a review: type (pink, red, green, gold, other), date, draft upload, reviewers and their sections.
- AI findings grouped by evaluation factor (Section M on federal bids): strengths, weaknesses, deficiencies, risks, each with the draft quote and page.
- Reviewers add findings by hand. Writers set a disposition per finding (accept, reject, done).
- Export: review summary (DOCX) and findings (XLSX).

### 3.7 Production checklist (paid)
- Standard checklist plus rules extracted from the solicitation (fonts, margins, page limits, file naming, portal, copies), each with source.
- Done checkboxes, owner, and a "ready to submit" bar.

### 3.8 Orals (paid, optional)
- Orals rules from the solicitation, each with source, a preparation checklist, and a session plan (topics, presenters, minutes).

### 3.9 Lessons learned (paid)
- Short survey after submission or award (what worked, what to change, evaluator feedback), plus notes. Export: DOCX.

### 3.10 Documents (all plans)
- Header: MB used of the bid's cap, for example "124 MB of 300 MB used". Free bids have 50 MB; Starter and Growth bids have 300 MB. All files on the bid count.
- List of files on the bid: name, kind (solicitation, amendment, attachment, resume, draft), amendment number, pages, size, upload date, live-until date, status (processing with queue position, live, archived, restoring, restored until a date, deleted), marking status.
- Upload checks, each with a plain message:
  - The file is larger than what is left of the cap: refused, with the MB left.
  - A second solicitation file with a different solicitation number: refused, "This file belongs to a different solicitation. Start a new bid." A file with no number can be added as an attachment.
  - The same file already on the bid (same sha256): "Already uploaded." No credit is used.
  - A PDF that needs a password to open: refused, "Upload an unlocked copy." Files with only permission restrictions are accepted.
- "Add amendment" checks the solicitation number before accepting (06 s4). On a mismatch, the bid owner sees "Override" with a required reason and the number of overrides left.
- Amendment number (04 s3.1): "Add amendment" has an optional number field (1 to 999). A number another amendment on the bid already has is refused: "Another amendment on this bid already has that number." With no number typed, the app reads it from the file (SF-30 block 2, "Amendment No.", "Addendum No.", or an "Amendment 3" heading on page 1); with none in the file it takes the next number on the bid and shows it as assumed. Any member can change the number from the list. A typed number that differs from the file shows "The file reads Amendment M". When the file's number is already taken, or page 1 names two numbers, the amendment waits with "Set the amendment number" and runs once a number is set.
- Marking prompt: "This file carries the marking [CUI] on page 2. AI processing is paused. Confirm the file is public or approved for third-party processing." Confirm or remove the file. The choice is logged.
- Archived files show "Restore". Status reads "Restore requested", then "Restoring (a short wait)", then "Restored until [date]". 🟨 **OPEN:** restore window length, any fee or limit, and whether free users can restore (07 s2).
- Delete a file. The tab rows and quotes it produced stay. Its MB is freed.

### 3.11 Bid settings (all plans)
- Name, agency, bid type (federal or SLED), solicitation number, start date, due date, time, and time zone. Changing dates, by hand or through an amendment, triggers the schedule's shift, scale, or keep prompt.
- Switch Orals on or off.
- Paid plans: the owner can extend how long files stay live on the server ("Keep files live until").
- Delete the bid, with the bid name typed to confirm. This also deletes its archive copies. A consumed RFP credit is not returned; a reserved one is released.

### 3.12 Row detail slider (shared component)

Opens on the right when a user clicks a row in any tab from 3.1 to 3.8. One component serves every source-bearing table (03 s3.1). Fields a table does not have are hidden.

| Field | Source |
|---|---|
| Verbatim source text | `source_quote`, shown exactly as stored |
| Section reference | `section_ref` (compliance rows) or `source_ref` (outline) |
| Document | File name of `document_id` |
| Page | `source_page`, to `source_page_end` when the quote crosses a page break |
| Amendment | "Original" or "Amd N"; supersede status with a jump link to the replacing row |
| Requirement type | `req_type` |
| Instruction and evaluation refs | `instr_ref`, `eval_ref` ("L ref" and "M factor" on federal bids) |
| Confidence | `confidence` |
| Flags | `flags` |
| Verified | `quote_verified`; `confirmed` for bid facts |
| Owner and status | `owner`, `status` |
| Origin | AI or user |
| Edit history | `row_history`: who changed which field, from what, to what, and when |

- Buttons: "Open source" (source viewer at that page), "Edit", "Close".
- Esc closes the slider and returns focus to the row. The table stays usable while it is open. Below 1,024 px it opens full width.

### 3.13 Source viewer (shared component)
- Opens the document's viewer copy at the page with the quote highlighted, across two pages when the quote crosses a page break. The viewer copy is the original PDF, the OCR'd PDF for scanned files, or the PDF converted from a Word file.
- Word files that could not be converted show page text with "Page estimated".
- After a file is archived, the viewer shows the stored quote and the page text, with a "Restore" button. The full page view returns once the file is restored.
- After a resume is deleted at 90 days, the viewer shows "Resume deleted after 90 days".
- The viewer uses a per-document viewing token valid about 1 hour and bound to the session. It renews quietly while the viewer is open.

## 4. States every tab handles

| State | Shows |
|---|---|
| No solicitation yet | Upload prompt |
| Processing | Step list with progress, queue position, and expected wait |
| Waiting for you | Marking confirmation, or amendment links to confirm |
| Failed | Plain-language reason and a retry button. No raw error text |
| Empty result | "No items found" plus the option to add by hand |
| Locked (free plan) | Tab description and upgrade button |
| Out of credits | Credits left, reset date, upgrade button |
| Over the MB cap | MB used and the cap, upgrade button on Free |

## 5. Accessibility and quality bar

- Keyboard reachable controls with visible focus.
- Text contrast at WCAG AA or better.
- Labels on every input; no placeholder-only fields.
- Tables scroll inside their own container; the page never scrolls sideways.
- Loading states: none under 100 ms, inline spinner up to 1 second, skeleton beyond.
- Destructive actions name the item and default focus to Cancel.
- Crossed-out rows also carry the text label ("Superseded", "Withdrawn"), not strike-through alone.
